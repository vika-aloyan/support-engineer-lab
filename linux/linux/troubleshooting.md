# Linux Troubleshooting

## Case 1 — Закончился свободный диск

### Симптом

Сервис перестал корректно работать. В логах появляются ошибки записи файлов.

### Диагностика

Проверяем свободное место:

df -h

Если диск заполнен, ищем директории, которые занимают много места:

du -sh /var/log/*

### Возможная причина

Большой объём логов или временных файлов.

### Решение

Удалить или архивировать ненужные файлы согласно правилам хранения данных и настроить ротацию логов.

### Проверка

Повторно проверяем свободное место:

df -h

После этого проверяем работоспособность сервиса.

## Case 2 — Сервис не работает

### Симптом

Пользователь сообщает, что сервис недоступен.

### Диагностика

Проверяем состояние сервиса:

systemctl status nginx

Проверяем последние записи в логах:

journalctl -u nginx -n 50

Проверяем открытые порты:

ss -tulpn

### Возможная причина

Сервис остановлен или завершился с ошибкой.

### Решение

После определения причины перезапускаем сервис:

systemctl restart nginx

### Проверка

Снова проверяем состояние:

systemctl status nginx

И проверяем доступность сервиса.

---

## Case 3 — Высокая загрузка CPU

### Симптом

Сервис работает медленно.

### Диагностика

Проверяем загрузку процессора:

top

Также можно найти процессы с высокой загрузкой CPU:

ps aux --sort=-%cpu

### Возможная причина

Один из процессов потребляет слишком много CPU.

### Решение

Анализируем процесс и его логи, после чего устраняем причину высокой нагрузки.

### Проверка

Повторно проверяем загрузку CPU и работоспособность сервиса.
