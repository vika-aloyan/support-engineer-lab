# Network Troubleshooting

## Case 1 — Не открывается сайт

### Симптом

Пользователь сообщает, что сайт не открывается.

### Диагностика

Проверяем доступность IP-адреса:

```bash
ping 8.8.8.8

Проверяем разрешение доменного имени:

nslookup example.com

Проверяем HTTP-соединение:

curl -I https://example.com
Возможная причина

Проблема с DNS, сетевым соединением или самим сервисом.

Проверка

Определяем, на каком этапе возникает проблема: DNS, сеть, HTTP или сервер.

Case 2 — Не работает DNS
Симптом

Сайт не открывается по доменному имени, но IP-адрес доступен.

Диагностика

Проверяем DNS:

nslookup example.com

Также можно использовать:

dig example.com
Возможная причина

DNS-сервер не отвечает или доменное имя не разрешается в IP-адрес.

Решение

Проверяем настройки DNS и доступность DNS-сервера.

Проверка

Повторно выполняем:

nslookup example.com
Case 3 — Порт недоступен
Симптом

Сервис запущен, но подключиться к нему невозможно.

Диагностика

Проверяем открытые порты:

ss -tulpn

Проверяем HTTP-соединение:

curl -I http://example.com
Возможная причина

Порт закрыт, сервис не слушает порт или соединение блокируется firewall.

Решение

Проверяем состояние сервиса, настройки firewall и конфигурацию порта.

Проверка

Повторно проверяем доступность порта и сервиса.

Case 4 — Медленное соединение
Симптом

Пользователь сообщает, что сайт или сервис работает медленно.

Диагностика

Проверяем задержку:

ping example.com

Проверяем HTTP-запрос:

curl -I https://example.com

Также проверяем загрузку сети и сервера.

Возможная причина

Высокая задержка сети, потеря пакетов или высокая нагрузка на сервер.

Решение

Определяем источник задержки и проверяем состояние сервера и сетевого соединения.

Проверка

Повторно проверяем задержку и время ответа сервиса.
